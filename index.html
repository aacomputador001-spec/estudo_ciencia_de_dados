Conceito 1 de 8

Business Intelligence (BI) / Inteligência de Negócios

Definição simples

BI é o jeito organizado de pegar dados da empresa e transformá-los em informação útil para decidir melhor. Pense como o "painel do carro" da empresa: mostra velocidade, combustível, temperatura e alertas para ajudar a dirigir.

Definição profissional

Em ambiente profissional, BI é um conjunto de processos, modelos, relatórios e ferramentas para coletar, preparar, analisar e apresentar dados de negócio de forma confiável, normalmente por meio de dashboards, métricas, relatórios e análises para tomada de decisão.

Por que existe

Porque empresas têm muitos dados espalhados em sistemas diferentes. Sem BI, cada área olha um pedaço da verdade e decide no escuro. BI resolve a dor de transformar dados dispersos em visão de negócio consistente.

Exemplo prático

Na Loja Aurora, BI pode mostrar: faturamento por mês, vendas por região, taxa de devolução, ticket médio e estoque baixo. O gerente não precisa abrir planilhas; ele vê um dashboard e age.

Ferramentas

Excel ajuda em análises rápidas; SQL consulta os dados; Power BI, Tableau e Looker Studio criam dashboards; bancos de dados e data warehouses guardam os dados organizados; Python aparece quando a análise fica mais complexa. A Microsoft descreve o papel do data analyst justamente como alguém que prepara, modela, visualiza e analisa dados com ferramentas como Power BI.

Diferença importante

BI não é só gráfico bonito. BI é o sistema de decisões; visualização é só uma parte dele.

Como responder em entrevista

Curta "Business Intelligence é o uso de dados, relatórios e dashboards para apoiar decisões de negócio."
Mais completa "BI reúne processos e ferramentas para coletar, organizar e analisar dados e transformar isso em indicadores, relatórios e dashboards que ajudam a empresa a tomar decisões melhores."

Perguntas de follow-up

  • "How is BI different from Data Analytics?"
  • "What tools are used in BI?"
  • "What is a BI dashboard?"
  • "Why is BI important for companies?"

Pegadinhas comuns

Atenção Dizer que BI é "apenas Power BI" é errado. BI é mais amplo que uma ferramenta. Dizer que BI serve só para mostrar números também é errado: ele serve para orientar decisão.

Mini exercício

Na Loja Aurora, o diretor pergunta: "Por que o faturamento caiu no último mês?" O que BI entregaria para ajudar?

Ver solução explicada
BI entregaria um dashboard com receita por dia, região, produto, canal de venda e comparação com meses anteriores. A resposta não é só "o faturamento caiu", mas onde, quando e em qual segmento caiu.

  4. Qual ferramenta é comum em BI?

Conceito 2 de 8

Data Visualization / Visualização de Dados

Definição simples

É transformar dados em gráficos, mapas, tabelas visuais e dashboards para enxergar padrões mais rápido. É como trocar uma parede de números por uma imagem que o cérebro entende melhor.

Definição profissional

Visualização de dados é a representação gráfica da informação, usando elementos como gráficos, linhas, barras, mapas e dashboards interativos para comunicar tendências, padrões, exceções e comparações. Tableau descreve isso como uma forma de entender tendências, outliers e padrões de forma acessível.

Por que existe

Porque muitos insights ficam escondidos em tabelas. Um gráfico certo mostra sazonalidade, queda, crescimento e anomalias em segundos. Sem visualização, a análise fica lenta e confusa.

Exemplo prático

Na Loja Aurora, um gráfico de linha mostra faturamento por mês; um gráfico de barras compara regiões; um mapa mostra onde vende mais; um scatter plot pode mostrar relação entre desconto e margem.

Ferramentas

Power BI e Tableau são fortes para dashboards; Excel é ótimo para começar; Looker Studio ajuda em painéis leves; Python (Matplotlib/Seaborn/Plotly) entra quando você quer mais controle ou automação.

Diferença importante

Visualização não é EDA. Visualização é a forma de mostrar dados; EDA é o processo de explorar os dados para entender o que está acontecendo. Visualização pode fazer parte da EDA, mas não é a mesma coisa.

Como responder em entrevista

Curta "Data visualization é a representação gráfica dos dados para facilitar entendimento e comunicação."
Mais completa "É o uso de gráficos, mapas e dashboards para tornar padrões, tendências e outliers visíveis, ajudando tanto a análise quanto a comunicação com pessoas não técnicas."

Perguntas de follow-up

  • "What makes a good chart?"
  • "When should you use a bar chart instead of a line chart?"
  • "How do you avoid misleading charts?"

Pegadinhas comuns

Atenção Achar que quanto mais cores, melhor. Em geral, o bom gráfico é o que comunica com clareza, não o que chama mais atenção. Outro erro é usar o tipo errado de gráfico para o tipo de dado.

Mini exercício

Qual visual você usaria para comparar vendas por região e por quê?

Ver solução explicada
Barras. É melhor para comparar categorias. Linha seria melhor se a ideia fosse ver evolução no tempo.

  3. Visualização serve só para apresentação?

Conceito 3 de 8

ETL Process / Processo ETL

Definição simples

ETL significa Extract, Transform, Load: extrair dados de fontes, transformar para ficarem úteis e carregar em um lugar final. Pense em pegar ingredientes, lavar/cortar/cozinhar e só depois servir o prato.

Definição profissional

ETL é um processo de integração de dados que consolida informações de várias fontes em um repositório unificado. Na etapa de transformação, os dados são ajustados por regras de negócio e, depois, carregados no destino, muitas vezes passando por staging tables.

Por que existe

Porque dados brutos raramente chegam prontos para análise. ETL cria padronização, confiança e compatibilidade entre sistemas. Sem isso, cada relatório "fala uma língua".

Exemplo prático

A Loja Aurora recebe vendas do site, do app e da loja física. ETL extrai os três, transforma datas e moedas, remove duplicados e carrega tudo num data warehouse para o dashboard mensal.

Ferramentas

SQL, Power Query, Azure Data Factory, SSIS, dbt, Python e data warehouses. Microsoft mostra ETL em Azure Data Factory e SSIS como formas de criar pipelines e transformações; IBM descreve ETL como processo de combinar, limpar e organizar dados para um dataset consistente.

Diferença importante

ETL não é sinônimo de limpeza. Limpeza pode acontecer dentro do ETL, mas ETL é o pipeline completo de extração, transformação e carregamento.

Como responder em entrevista

Curta "ETL é o processo de extrair dados, transformá-los e carregá-los em um destino analítico."
Mais completa "ETL integra dados de várias fontes, aplica regras de negócio e padronização, e entrega uma base confiável para análise e BI."

Perguntas de follow-up

  • "How is ETL different from ELT?"
  • "What happens in each ETL step?"
  • "Why do we use staging tables?"

Pegadinhas comuns

Atenção Dizer que transformação é só trocar o formato da coluna é pouco. Transformação também inclui regras de negócio, padronização, agregação e preparação para o destino.

Mini exercício

Você recebeu arquivos CSV de 3 sistemas com datas em formatos diferentes. O que faz no ETL?

Ver solução explicada
Extrai os arquivos, transforma datas para um padrão único, padroniza nomes e tipos, remove duplicados e carrega tudo em uma tabela final pronta para BI.

Data Modeling / Modelagem de Dados

Definição simples

É organizar os dados para que façam sentido e sejam fáceis de consultar. É como desenhar o mapa de uma cidade antes de construir ruas e bairros.

Definição profissional

Modelagem de dados é a definição da estrutura, relacionamentos, granularidade e regras dos dados para suportar análise, relatórios e performance. Em BI, isso normalmente aparece como um modelo estrela, com fatos e dimensões.

Por que existe

Porque dados "achatados" ou mal relacionados geram relatórios lentos, confusos e errados. Um bom modelo facilita consultas, reduz ambiguidade e melhora governança.

Exemplo prático

Na Loja Aurora, você pode ter uma tabela fato Sales com DateKey, ProductKey, CustomerKey, Revenue e Quantity; e dimensões Date, Product, Customer, Region. Assim você analisa vendas por mês, produto ou região sem duplicar lógica.

Ferramentas

Power BI, Tableau, Excel Power Pivot, SQL, dbt e bancos relacionais. A Microsoft destaca que modelos semânticos e star schema são bases de relatórios e visualização; Tableau também trata dimensões e medidas como blocos centrais da análise.

Diferença importante

Modelagem não é só "juntar tabelas com join". Ela define a estrutura lógica correta para perguntas de negócio, não apenas a união física dos dados.

Como responder em entrevista

Curta "Data modeling é organizar tabelas e relacionamentos para analisar dados de forma eficiente."
Mais completa "É a definição de fatos, dimensões, granularidade e relacionamentos para que relatórios e consultas sejam consistentes, rápidos e fáceis de entender."

Perguntas de follow-up

  • "What is a fact table?"
  • "What is a dimension table?"
  • "Why is star schema popular in BI?"

Pegadinhas comuns

Atenção Confundir fato com dimensão. Dimensão descreve o "quem/onde/quando/o quê"; fato mede "quanto". Outro erro é criar muitos relacionamentos complexos sem necessidade.

Mini exercício

Na Loja Aurora, quais seriam fatos e quais seriam dimensões?

Ver solução explicada
Fatos: receita, quantidade vendida, desconto, custo. Dimensões: data, produto, cliente, região, canal.

Data Cleaning, Data Transformation e Data Integration

Definição simples

Data Cleaning = arrumar erros.
Data Transformation = mudar a forma/estrutura dos dados para ficarem úteis.
Data Integration = juntar dados de fontes diferentes em uma visão única.

Definição profissional

Cleaning corrige problemas como nulos, duplicados e valores inválidos; transformation converte tipos, cria campos, normaliza e agrega; integration combina dados de múltiplos sistemas em um formato harmonizado.

Por que existe

Porque dados do mundo real vêm imperfeitos e espalhados. Sem isso, a análise gera conclusões erradas. Boa limpeza e integração aumentam confiabilidade e uso analítico.

Exemplo prático

Cleaning: remover pedidos duplicados.
Transformation: converter 01/01/2026 e 2026-01-01 para o mesmo formato; criar Month.
Integration: unir site, app e loja física em uma tabela única de vendas.

Ferramentas

Power Query, Excel, SQL, Python/Pandas, dbt, Azure Data Factory, SSIS. Microsoft mostra limpeza com Power Query e DQS; IBM e Microsoft mostram integração e transformação como parte de ETL e pipelines.

Diferença importante

Cleaning não é Transformation. Exemplo: corrigir "Sao Paulo" para "São Paulo" é cleaning; criar a coluna Revenue = Price * Quantity é transformation. Integrar é juntar fontes; transformar é mudar os dados já dentro do fluxo.

Como responder em entrevista

Curta "Cleaning corrige erros; transformation prepara e reorganiza os dados; integration combina dados de várias fontes."
Mais completa "São etapas complementares: primeiro eu corrijo problemas de qualidade, depois transformo tipos e estruturas para análise, e por fim integro diferentes fontes em uma visão única e confiável."

Perguntas de follow-up

  • "What are common cleaning issues?"
  • "When would you transform data?"
  • "Why is integration hard across systems?"

Pegadinhas comuns

Atenção Dizer que transformar e integrar são a mesma coisa. Não são. Integrar é combinar fontes; transformar é mudar a forma dos dados. Outro erro: achar que cleaning é opcional. Em geral, não é.

Mini exercício

Como você trataria datas em formatos diferentes e clientes duplicados?

Ver solução explicada
Padronizaria as datas com transformação, removeria/mesclaria duplicados com cleaning, e só depois integraria tudo na base final.

Quiz rápido

  1. Qual etapa corrige duplicados?
  2. Qual etapa junta fontes diferentes?
  3. Qual etapa cria novos campos?
  4. Cleaning pode fazer parte do ETL?
  5. Transformation sempre muda o conteúdo?

Data Quality / Qualidade de Dados

Definição simples

É o quanto os dados são bons para o uso pretendido. Dados de qualidade são corretos, completos, consistentes e confiáveis.

Definição profissional

Data quality é o grau em que um conjunto de dados atende critérios como accuracy, completeness, validity, consistency, uniqueness, timeliness e fitness for purpose. Microsoft também trata qualidade por regras e scores para medir se o dado está em estado aceitável.

Por que existe

Porque uma análise só é tão boa quanto os dados por trás dela. Dados ruins produzem dashboards ruins, decisões ruins e desconfiança na área de dados.

Exemplo prático

Na Loja Aurora, se a mesma venda aparece duas vezes, a receita fica inflada. Se a data está vazia, o relatório mensal quebra. Se Region tem SP, Sao Paulo e São Paulo, a análise regional fica distorcida.

Ferramentas

Excel e SQL ajudam a detectar problemas; Power Query limpa; Power BI e Purview podem medir qualidade com regras e scores; Python ajuda a automatizar checagens; DQS e outros catálogos ajudam na governança.

Diferença importante

Data quality não é só "ter dados bonitos". É ter dados adequados para a finalidade. Um dado pode estar tecnicamente correto e ainda assim ser inútil para a pergunta errada.

Como responder em entrevista

Curta "Data quality é o grau de confiabilidade e adequação dos dados para o uso pretendido."
Mais completa "É a avaliação de critérios como completude, consistência, validade e atualidade. Sem qualidade de dados, qualquer análise ou KPI pode se tornar enganoso."

Perguntas de follow-up

  • "How do you measure data quality?"
  • "What is a data quality rule?"
  • "Why do duplicates hurt reporting?"

Pegadinhas comuns

Atenção Pensar que qualidade é só ausência de erro. Também envolve consistência, atualidade e adequação ao objetivo. Outro erro é medir só uma coluna e ignorar o contexto do negócio.

Mini exercício

Uma coluna tem 5% de valores nulos. Isso é sempre um problema?

Ver solução explicada
Não necessariamente. Depende da coluna e do uso. Se for uma coluna essencial, pode ser grave; se for opcional, talvez seja aceitável. Qualidade depende do contexto.

Quiz rápido

  1. O que é completeness?
  2. O que é consistency?
  3. Dados de boa qualidade garantem decisão certa?
  4. Qualidade depende do uso?
  5. O que acontece com duplicados em receita?

Conceito 7 de 8

Metrics, KPIs and Dimensions

Definição simples

Uma metric é qualquer medida numérica. Um KPI é uma métrica-chave ligada a um objetivo importante. Uma dimension é um eixo de análise, como tempo, região, produto ou cliente. Tableau e Microsoft tratam medidas e dimensões como blocos fundamentais de análise.

Definição profissional

Métricas quantificam algo; KPIs são as métricas que realmente representam o sucesso de um objetivo; dimensões são atributos categóricos ou descritivos usados para segmentar e analisar as métricas.

Por que existe

Empresas precisam medir desempenho. Mas nem toda métrica importa. KPIs evitam que a equipe se perca em números irrelevantes. Dimensões permitem perguntar "em qual região?", "em qual produto?", "em qual mês?".

Exemplo prático

Na Loja Aurora: Metric = número de pedidos. KPI = taxa de conversão ou receita mensal. Dimensions = região, produto, mês, canal. Você pode medir KPI por dimensão: receita por região, conversão por canal, ticket médio por mês.

Ferramentas

Power BI e Tableau para visualizar; SQL para calcular; Excel para testar fórmulas; Looker e dbt para métricas padronizadas; catálogos e camadas semânticas ajudam a manter uma definição única.

Diferença importante

Toda KPI é uma métrica, mas nem toda métrica é KPI. Isso é uma das pegadinhas mais comuns. Dimensão não é medida: dimensão segmenta; medida quantifica.

Como responder em entrevista

Curta "Metric is any number you track; KPI is a key metric tied to a goal; dimension is a descriptive field used to slice the metric."
Mais completa "Métricas são medidas numéricas, KPIs são as métricas mais importantes para objetivos de negócio, e dimensões são os atributos que usam para segmentar a análise."

Perguntas de follow-up

  • "What is the difference between a metric and a KPI?"
  • "Can a KPI change over time?"
  • "What is a measure vs a dimension?"

Pegadinhas comuns

Atenção Chamar tudo de KPI. Isso enfraquece a análise. Outro erro é colocar um texto como medida. Se o campo serve para segmentar, ele é dimensão.

Mini exercício

Em um dashboard de vendas, classifique: Revenue, Region, Orders, Conversion Rate.

Ver solução explicada
Revenue e Orders são métricas; Conversion Rate pode ser KPI se for objetivo principal; Region é dimensão.

  2. Região é métrica ou dimensão?
  3. Toda métrica é KPI?
  4. O que significa "slice" da análise?

Conceito 8 de 8

EDA (Exploratory Data Analysis) / Análise Exploratória de Dados

Definição simples

EDA é a etapa de "conhecer" os dados antes de tirar conclusões ou criar modelos. Você olha distribuições, valores faltando, padrões, relações e outliers. Databricks e Microsoft descrevem EDA como uma forma de revisar o dataset cedo para entender melhor o que ele contém.

Definição profissional

EDA é um processo iterativo de exploração visual e estatística para resumir o comportamento dos dados, levantar hipóteses, detectar problemas de qualidade e orientar decisões analíticas ou de modelagem.

Por que existe

Porque não faz sentido construir análise ou modelo sem entender a base. EDA revela erros, padrões, relações e anomalias que mudam completamente a interpretação.

Exemplo prático

Na Loja Aurora, antes de criar o dashboard, você faz EDA e descobre que: 8% das datas estão vazias, há duplicados, algumas regiões aparecem com nomes diferentes e as vendas têm pico em novembro. Isso muda o que você vai limpar e como vai modelar.

Ferramentas

Python com Pandas, Matplotlib e notebooks; Excel para olhar amostras; SQL para consultas exploratórias; Power BI/Tableau para exploração visual; Databricks e Fabric para notebooks e fluxos analíticos.

Diferença importante

EDA não é "fazer gráfico porque sim". Ela tem intenção investigativa: entender os dados, levantar hipóteses e achar problemas antes da fase final.

Como responder em entrevista

Curta "EDA is the step where we explore the data to understand distributions, relationships, and potential problems."
Mais completa "Exploratory Data Analysis é a exploração inicial dos dados, usando estatística e visualização para entender o dataset, encontrar outliers, detectar problemas de qualidade e orientar a análise ou modelagem."

Perguntas de follow-up

  • "What do you look for in EDA?"
  • "Why is EDA important before modeling?"
  • "Which charts are useful in EDA?"

Pegadinhas comuns

Atenção Fazer EDA só depois de tudo pronto. O certo é EDA cedo. Outro erro é ignorar o contexto do negócio e olhar apenas números sem interpretar.

Mini exercício

Quais 3 coisas você investigaria primeiro em uma nova base de vendas?

Ver solução explicada
Tipos de dados, valores faltantes/duplicados e distribuição das vendas por tempo, região e produto.

Quiz rápido

  1. EDA vem antes ou depois da limpeza?
  2. O que é um outlier?
  3. EDA ajuda a criar hipóteses?
  4. EDA usa só visualização?
  5. O que você checa primeiro em uma nova base?

Conectando os pontos

Diferenças entre conceitos parecidos

BI × Data Analytics

BI organiza dados para apoiar decisões do negócio, geralmente com foco em relatórios, dashboards e acompanhamento operacional; data analytics é a investigação e interpretação dos dados para encontrar padrões e responder perguntas, e costuma ser uma parte do trabalho maior de data science.

Data Cleaning × Data Transformation × Data Integration

Cleaning corrige problemas; transformation muda formato/estrutura/valor para uso analítico; integration une múltiplas fontes em uma visão única.

Data Visualization × EDA

Visualização é a forma de mostrar dados; EDA é o processo de explorar e entender os dados. Uma pode existir sem a outra, mas geralmente trabalham juntas.

Metrics × KPIs × Dimensions

Metric = qualquer número medido; KPI = métrica-chave ligada a objetivo; dimension = eixo de segmentação.

Dimension × Measure

Dimension descreve e segmenta; measure agrega e quantifica. Tableau identifica campos como dimensões ou medidas para montar análise.

Conectando os pontos

Ferramentas na prática, por contexto

Excel é ótimo para inspeção rápida, protótipos e validação manual. SQL é a linguagem mais importante para consultar bases e testar hipóteses. Python + Pandas ajudam em limpeza, transformação, EDA e automação. Power BI e Tableau entram quando você quer modelar, criar métricas e visualizar para a empresa. dbt aparece muito na transformação e padronização de modelos analíticos. Bancos de dados e data warehouses guardam a base preparada para BI. Microsoft e Tableau mostram claramente como modelagem, limpeza, visualização e análise se conectam em fluxos de dados modernos.

Os dados brutos chegam bagunçados. A limpeza corrige erros; a transformação padroniza e cria campos úteis; a integração junta fontes diferentes; a modelagem organiza fatos e dimensões; a EDA ajuda a entender o dataset; BI usa isso para criar relatórios e dashboards; a visualização comunica o resultado; e a empresa toma decisão com mais confiança. Na prática, essas etapas podem se misturar, voltar para trás e repetir, porque projetos reais raramente são lineares.

Simulação de entrevista para Junior Data Analyst / BI Analyst

Vou deixar o formato pronto para você treinar. Responda uma por vez e eu avalio no mesmo estilo que você pediu.

Pergunta 1: What is Business Intelligence?

O que o entrevistador quer saber: se você entende a finalidade de BI e não só a palavra.

Resposta ruim"É fazer dashboards."
Resposta boa"BI é o uso de dados para gerar relatórios e apoiar decisões."
Resposta excelente"Business Intelligence é um conjunto de processos e ferramentas que coletam, organizam, analisam e apresentam dados de negócio para transformar informação em decisão."

Pergunta 2: What is the difference between Metrics and KPIs?

O que quer saber: se você sabe priorizar indicadores.

Resposta ruim"É a mesma coisa."
Resposta boa"Métrica é qualquer número; KPI é a métrica mais importante para um objetivo."
Resposta excelente"Toda KPI é uma métrica, mas nem toda métrica é KPI. KPI mede o progresso de um objetivo específico; métricas apoiam a análise, mas nem todas têm valor estratégico."

Pergunta 3: What would you do if a dashboard shows unexpected revenue?

O que quer saber: se você pensa com EDA, qualidade e modelagem.

Resposta excelente esperadaInvestigar a base, checar duplicados, datas, filtros, transformação e fonte dos dados antes de concluir que o negócio mudou.
